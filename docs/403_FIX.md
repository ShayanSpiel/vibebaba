# Fix for 403 Permission Errors

## Problem
After creating the workflow logging collections with restricted permissions, the admin API was getting 403 errors when trying to read the logs.

**Error:**
```
ClientResponseError 403: Only admins can perform this action.
```

## Root Cause
The `/api/admin/workflow-health` route was using an **unauthenticated** PocketBase client:
```typescript
const pb = new PocketBase('http://localhost:8090');
```

But the collections now have these rules:
- `listRule: null` (admin-only read)
- `viewRule: null` (admin-only read)
- `createRule: ''` (allows server-side logging)

## Solution ✅

Updated the API route to use the **admin-authenticated** PocketBase client:

### Before:
```typescript
import PocketBase from 'pocketbase';

const pb = new PocketBase(process.env.NEXT_PUBLIC_POCKETBASE_URL || 'http://127.0.0.1:8090');

export async function GET(req: NextRequest) {
  return requireAdmin(req, async (req, user) => {
    // pb here has NO authentication ❌
    const logs = await pb.collection('workflow_execution_logs').getFullList();
  });
}
```

### After:
```typescript
import { getAdminPb } from '@/lib/pocketbase-admin';

export async function GET(req: NextRequest) {
  return requireAdmin(req, async (req, user) => {
    // Get admin-authenticated client ✅
    const pb = await getAdminPb();
    const logs = await pb.collection('workflow_execution_logs').getFullList();
  });
}
```

## What Changed

**File**: `app/api/admin/workflow-health/route.ts`

1. Replaced `import PocketBase` with `import { getAdminPb }`
2. Removed global `pb` constant
3. Added `const pb = await getAdminPb()` inside both GET and POST handlers

## How getAdminPb() Works

From `lib/pocketbase-admin.ts`:
```typescript
export async function getAdminPb(): Promise<PocketBase> {
  // Returns cached authenticated client if available
  if (adminPb && adminPb.authStore.isValid) {
    return adminPb;
  }

  // Otherwise authenticates with admin credentials from .env.local
  adminPb = new PocketBase(PB_URL);
  await adminPb.admins.authWithPassword(ADMIN_EMAIL, ADMIN_PASSWORD);

  return adminPb;
}
```

**Environment Variables Used:**
- `POCKETBASE_ADMIN_EMAIL=admin@vibebaba.com`
- `POCKETBASE_ADMIN_PASSWORD=admin1234567890`

## Result

✅ Admin panel API now works correctly
✅ Workflow health dashboard loads data
✅ No more 403 permission errors
✅ Collections remain secure (admin-only read access)

## Security Notes

This approach is secure because:
1. The API route already requires admin authentication via `requireAdmin()` middleware
2. Only authenticated admin users can access `/api/admin/workflow-health`
3. The PocketBase admin client is only used server-side
4. Collections still have `listRule: null` preventing client-side access
